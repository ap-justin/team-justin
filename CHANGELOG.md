## v0.10.0 — what the handoff doesn't name, the builder invents

**The lead now runs every builder brief against a seven-item contract, and that list is half of Step 3's completion criterion.** The obligations were always there — scoped paths, the behavior list, the exemption, the closed set, the props contract, the states to reach, the primitive library, the learnings channel, the report path — but they were scattered across ten sites between the routing table and Step 4, which is the co-location failure: one meaning fragmented until attending to all of it is a coin-flip. They now sit as one numbered list right after the grouping rule, each pointing at the block that holds its mechanism. **Item 3 is the new one:** *every decision the slice contains*. A question handed down for a builder to **investigate** must also name what each answer resolves to — "grep for X, report it, leave the file either way" is a brief; "check X, then decide what to do" is a decision delegated by accident. The failure it fixes was observed, not theorized: a brief that asked a builder to check whether any CSS selected `:invalid` "before you decide what to do with the attachment" got a deleted file back, along with the comment block explaining why the attachment existed.

**Ambient blocks are handed down by pointer, never re-authored — because the drift lands on exactly the clause that was load-bearing.** Comments, TypeScript, test-first, tokens and official sources each already ride in the seat prompt or the repo's own docs, each with one canonical text. The lead had a rule against restating *sources* and a rule against restating *token values*, and no rule covering the rest — so a handoff re-typed `## Comments (earn the line)` from memory as five prohibitions, dropping both clauses `shared-blocks.md` marks ⚠: the **positive target** ("earns its line by carrying what the code can't", without which the block reads as *fewer comments*) and the **`comments already in the file survive your edit`** bound (without which a pruning rule reads as a licence to delete). Both failure modes were documented in Block I a version earlier; the re-authoring stripped them and the predicted deletion followed. The rule is now general and states its own evidence.

**`## Rules` is gone — 1,066 words restating the body it sat under.** Nearly every bullet ended in "(Step N)", which is an admission: a pointer to in-file content is duplication, not disclosure, and it inflated those meanings past their real rank while doubling the maintenance surface. Six bullets carried content found nowhere else and were **relocated to where the mechanism already lives** rather than deleted — the size axis of splitting and *One task, one builder* into Step 3 beside the seat axis they cross-reference, the shadcn token convention into *Conformance is prevented, not detected*, the `/roster learn` sweep into the learnings channel, phase reporting into the talk-to-a-PM principle, and the version/roster line up with the other plugin pointers. Each of the remaining thirteen was checked against its body text before deletion.

**Two branch-only sections moved behind pointers.** The ten-step greenfield design sequence (`references/greenfield-ui.md`, with the gallery review passes and the greenfield-only `pnpm` default) and the screen-pass briefing detail (`references/screen-passes.md`) only ever fire on a greenfield build or a UI review — the second one even told the reader "wire them at Step 4, not here," which is the smell. Both keep their original headings in `SKILL.md` with a summary and a pointer, so `ROSTER.md`, `TRACKER.md` and `agents/ux-designer.md`'s references to *Step 2, Greenfield UI* still resolve.

**The recurring read falls, the corpus doesn't shrink.** `SKILL.md` goes 10,899 → 9,336 words (−14%) against a total of 10,951 across the three files — the same relocation-not-deletion accounting the lead's own `lossless-doc-compaction.md` demands of the plan stores it curates. Negations drop from 91 `never`/`don't` to 63, concentrated on the register the lead quotes into handoffs: the contract and the ambient-blocks rule are written as positive targets, since a skill that steers by prohibition produces briefs that steer by prohibition. No agent added, no seat retired — the count stays at 25.

## v0.9.0 — a corpus you consult, not a list you carry

**The team gets a place to put a UI pattern, and it is not a seat prompt.** `skills/ui-patterns/` is a corpus **indexed by what you're about to build** — a form and its validation, a list row and its repeated control, an icon beside a wrapping label, a selectable row that can also hold focus. `SKILL.md` is the index and nothing else: match the build target, load the **one** `reference/` group, leave the other two alone. That's the whole reason it's a consulted corpus instead of a block in a prompt — a prompt pays for every pattern on every build, including the ones about components this slice doesn't contain, while an index pays for the one file that applies. It's the same shape `ux-principles` already runs (grouped by flow step, two or three groups per walk), with one substitution: the group key is the thing being built rather than the step being audited.

**`CURATION.md` carries the bar, and the bar is the point.** Every entry names the **default it corrects** — the specific wrong thing that gets written when nobody consults the file — and if that field can't be written, the entry doesn't go in. It's authored first and printed second, under the pattern itself: naming a wrong shape makes that shape more available, so the reader lands on what to do and reads the corrected default underneath as recognition. A true, useful, widely-agreed pattern a careful builder would produce anyway is padding. The consequence is the bound a flat pattern list never had: the corpus grows with the number of **wrong defaults**, not with the number of preferences the user has, so it can absorb every sweep without becoming something nobody reads. The file is authoring-only and unreferenced from `SKILL.md`, so it costs nothing at build time — same posture as `ux-principles`' own `CURATION.md`.

**A second bar keeps the corpus from arguing with the design system.** Every entry is **design-system agnostic** — behavior, sequence, semantics, grouping, layout mechanics, all of it holding identically under any token file. Appearance is out — rank, ink, borders, underlines, indicators — because the token file settles those, settles them per project, and outranks this corpus in every repo that has one. A pattern about a look is dead weight where the system overrides it, and worse than dead weight where it *contradicts* it: two authoritative files disagreeing, with the builder guessing. The test is one question — could a good design system ship the opposite and still be good? — and it runs on the whole entry, not on a core carved out of one. Focus-versus-selection is the case that settles the method: it has a real behavioral residue (both states are reachable at once), and it still comes out, because every mark it turns on is the system's and what's left only makes sense next to the look it lost.

**Eight entries seeded, in three groups.** `forms-and-mutations` carries five: a form's first validation pass is its **submit** and the correction pass is **on change**, so nothing goes red mid-keystroke and nothing makes the user press submit again to learn whether their fix took; a failed submit **moves focus to the first invalid field**, one gesture that scrolls it into view, announces it, and puts the caret where the edit has to happen; the control that caused a mutation reports its own outcome in place; a toast is only for an outcome landing on a different screen, carried as a one-shot flash; a same-screen save doesn't move the scroll position. Then `lists-and-rows` (a repeated control names its own row to assistive tech while the visible word stays constant) · `text-and-icons` (an icon aligns to its label's **first** line via a one-line-tall box, not the block's center or a hand-tuned margin; no prose for what the UI already demonstrates).

**The validation ladder narrows a rule the canon already owns, rather than restating it.** `ux-principles` → *Validate after the user finishes, not while they're mid-keystroke* permits blur **or** submit; the house entry picks submit for the first pass and adds the correction pass, and one clause on the canon entry records that so `ux-auditor` and the builders can't diverge. The three framework seats gained the stack half — the error map that comes back with the render, `useActionState`, `useActionData`/`fetcher.data`, `fail(400, { form })` under `use:enhance` — leaving the ladder itself in one file.

**Wired to three kinds of reader, and the rule lives in exactly one file.** The two **UI component builders** load it ambiently at build time. The three **framework builders** load `forms-and-mutations` and keep only their **stack mechanism** — SvelteKit's `cookies.set` before the redirect and `cookies.delete` in the root layout's load (and the fact that a `redirect` to the same URL is a navigation, so it resets scroll), RR7's `session.flash()` and `useFetcher`, Next's middleware clear because a render can't delete a cookie. **`ux-designer`** reads the same corpus when it specs a component, so a handoff spec can't contradict the build it's handed to — which is what "ask the designer" would have bought, minus the two hops through the lead that a builder (no self-dispatch) would have had to pay per slice. `modern-css` keeps ownership of whether `lh` needs a fallback and points at the pattern rather than restating it: two files stating one rule is the failure this corpus exists to prevent.

**The preference loop now has a destination that scales.** `PREFERENCES.md` → *The destination* and `roster/learn.md` route a component-level `[design]` keeper to a corpus entry instead of a targeted prompt edit; a rule with a stack mechanism splits, rule to the corpus and mechanism to the seat. Six seats each carrying a copy of one preference was the shape the sweep was heading for, and it's the shape that drifts. The second bar gives the sweep a third outcome besides promote-or-drop: a preference about how something *looks* is returned to the user as the project design system's call, since that's the file it would have fought. No seat added — the count stays at 25.

## v0.8.0 — a comment earns its line

**Every code-writing seat now carries a comment rule, because the default is bloat.** Agents comment at a rate no human would: a line above each line restating it, a header narrating the change just made, a sentence explaining the work to whoever prompted it. `## Comments (earn the line)` is **Block I** in `skills/roster/shared-blocks.md`, byte-identical on the **15 seats** that write code — every seat carrying Block B, sitting immediately after it, because TypeScript and comments are the same kind of thing: ambient craft in the code the seat is already writing, not a hand-off. The rule is four bullets. A comment carries what the code can't (a constraint from outside the file, why a correct-looking alternative is wrong, the gotcha waiting for the next reader); it is written in the **present tense with no archeology** — what it replaced, what was tried first, what the brief said, all of which git already holds; it addresses the next reader of the file rather than the prompter; and terse beats grammatical, fragments included.

**Its two failure modes are held open on purpose, marked ⚠ in the block.** Drop *present tense, no archeology* and the seat narrates its own session into the file, which is the largest source of bloat and the fastest to go stale — but the paired clause matters as much: a reason that outlives the session **is** *why* and stays, because it's the thing no config confesses. Drop *comments already in the file survive your edit* and a pruning rule reads as a licence to delete, which on brownfield makes the whole block a net loss. The bound is what a seat **writes**, never what it **finds**.

**No pass enforces it, and that's the design.** Comment density is a writing default, not a review dimension — a reviewer flagging it would spend findings the lead routes on. It rides in the seat prompt where the writing happens; `/roster audit` step 6 asserts the block is *present and identical* across all 15 (no tailored slot, so any divergence is drift), and `hire` copies it from the canonical file rather than from a peer. `graphic-designer` is exempt with the reason recorded: its p5.js output comes from the `algorithmic-art` template, whose heavy instructional comments are exactly what marks the sections a later run replaces. The lead is bound too — its own inline stack-agnostic edits meet the same bar. The team already ran *present tense, no archeology* on its **seat prompts**; the same vocabulary now covers the code those seats write.

## v0.7.0 — the system decides, the team conforms

**A React repo already on shadcn had no source.** `react-ui-builder` was told *component-library APIs via Context7, never from memory*, which is the right instruction when a library ships only docs. shadcn ships a first-party **skill** — one that runs `shadcn info --json` as it loads and hands back the repo's own `aliases`, `base`, `iconLibrary`, `tailwindVersion` and installed-component list — so Context7 was the fallback standing in for a source that exists. It's now vendored at `skills/shadcn/` from `shadcn-ui/ui@efac598` (MIT, verbatim minus the Codex metadata, eval fixtures and branding PNGs). Nothing needed porting: `user-invocable: false`, `allowed-tools` and `` !`cmd` `` injection are all native Claude Code frontmatter, so the project-context block genuinely executes rather than reading as a promise. Vendored rather than `pnpm dlx skills add shadcn/ui` per project, for the reason the whole repo is a plugin — `~/.claude` doesn't exist on the web VM.

**The team now carries two primitive libraries, and the reach-for rule stays in one file.** Ark UI is unchanged for Vue/Solid/Svelte and already-on-Ark repos; shadcn is the playbook wherever a root `components.json` says the repo made that choice already. The one open call — greenfield React — belongs to the lead's plan, and the builder asks rather than defaults. All of it is written **once**, in `ark-ui`'s reach-for section, because two skills each stating half a rule is how the halves drift; `react-ui-builder` and `SOURCES.md` point at it instead of restating it. Whichever library lands, it is the only one in that repo from then on.

**The team stops legislating what a design system must contain.** A hard rule — *never opacity/alpha as a lightener* — sat under three mandated divergences from shadcn's stock theme (solid state steps instead of `bg-primary/90`, solid dark `--border`/`--input`, `--success`/`--warning` required), and `/taste-review` FAILed the banned shapes on sight. That is the pass overruling the system it exists to enforce: whether a hover step is a named solid, an alpha step or a `color-mix()` is a design decision, made in `claude-design`, and a build using what its token file offers was conforming the whole time. The vocabulary stays fixed and closed — that's what keeps *"is this value in the system"* a grep. The values and the technique behind them are the system's, and the team follows them.

**What the director may still override, and it is now only two things.** *Floor violations* was the one place `design-director` edits the creative return; it listed opacity beside a pair below AA. Technique is out of it — what's left is **accessibility** (a pair below AA) and **coverage** (a missing dark set, a state in the ladder that no token names). The state ladder itself is still required to *exist* in the file, in whatever shape the design gave it, because an unnamed state is the gap that sends a builder off to invent a value; `--success`/`--warning` became available-when-the-inventory-needs-them rather than mandated. Block E lost two of its three traps and gained the rule behind their removal — *how a value was derived is the system's business, not yours* — propagated byte-identical to both UI builders, and `/taste-review` lost the opacity check outright with the reason recorded inline so it doesn't grow back.

**Two survivors of the same habit, found by re-reading the director against its own rule.** The direction brief listed *none of the three AI-cluster looks (cream+serif+terracotta / black+acid-accent / hairline broadsheet)* among its **hard floors** — a verdict on the look, handed to `claude-design` in the same breath as AA and 375, and negation-steering besides: it names three aesthetics immediately before asking for a design. `frontend-design` already says the sane version of this to whoever is actually drawing (*they're defaults rather than choices; where the brief pins a direction, the brief wins*), so the pack stays loaded as calibration for the director and stops being content for the brief. A look the project genuinely doesn't want is the **user's** to name, and it already has a home — the anti-adjectives and anti-references in item 2. The floors list now carries a test of its own: every floor is accessibility, coverage or vocabulary, and one that would rule out a *look* has stopped being a floor. Second, the token contract read *"the emission format for every project the team builds"* — unqualified, so it bound a brownfield repo that already had its own names. It's the format for a system the team **starts**; an existing token file has already answered, its names win (a shadcn install's own theme included), and renaming one to match is a migration nobody asked for.

`/accessibility-review` and `/visual-review` were audited on the same axis and needed nothing: every a11y finding carries a WCAG criterion number, an authored pair that fails routes to `design-director` as a *system* defect rather than an argument about the palette, and the visual pass's verdict is explicitly about breakage, never about whether the design is right.

**Which lands the shadcn repos in the same place by a shorter route.** The carve-out this release originally shipped — *don't report vendor-generated `components/ui/*`* — existed only because the team's rules disagreed with shadcn's own theme. With the rules gone the exception is gone with them: the installed theme *is* the system, Block E applies to it unchanged, and stock components stay as the CLI wrote them so the next `add --diff` has nothing to reconcile.

## v0.6.0 — a seat per file, not per feature

**The lead routed a React fix list to `stripe-specialist`.** A donation-checkout review came back as eleven findings across eight files — bfcache `pagehide`/`pageshow` semantics, a cross-frame `postMessage` ack, React unmount disposal, a `done` state on a wallet rail, `paypal.tsx` — and the whole list went to the payments seat, which writes no React. Three defects in the routing prompt lined up to produce it, and each is fixed at its own cause rather than papered over with a warning.

**The stripe and auth rows stop paraphrasing a boundary that has its own home.** `stripe-specialist.md` has said *Builder owns: pricing UI, buttons, **redirect/embed wiring**, and the route file* since it shipped; the lead's routing row carried a second, shorter copy — *the pricing page + buttons → the UI builder* — that had quietly dropped the embed clause, which is exactly the clause three of the findings sat under. One boundary in two files drifts, and the lead routes off whichever copy it can see. Both rows now point at the seat's own `Builder owns` line instead of restating it (the discipline Step 3 already asserts for official sources), and each row's triggers are qualified to **the server + money / server + session half** so a `.tsx` under `stripe/` no longer fires them on the directory name.

**The UI seam stops being a roster of three.** It opened *Framework seats (`sveltekit-builder`, `react-router-builder`, `nextjs-builder`) own the network boundary…* — a closed enumeration that left the domain seats outside the rule, so nothing pulled the component half back out of a payments dispatch. It now leads with the property instead of the membership: **only `react-ui-builder` and `svelte-ui-builder` write components**, every other seat hands component implementation across, and **a file's directory does not own it** — `methods/stripe/form.tsx` is a component that happens to live under `stripe/`.

**Splitting gains its missing axis.** The skill has always opened *Delegate on stack, not size*, then defined splitting only by size ("a build that would touch many files/subsystems"). Nothing said to split when the **file set crosses a seam**, so a change list explicitly annotated with paths across four rails read as one unit. Step 3 now carries the grouping rule — **the table picks a seat per file, not per task; more than one group is more than one dispatch** — which doubles as the step's completion criterion (*every file in the change list assigned to a seat*, which a single guess never satisfies). Step 4's fix loop inherits it, since a merged multi-reviewer fix list is where the singular "loop fixes back to the builder" did its damage, and the size bullet now names itself as the other axis.
