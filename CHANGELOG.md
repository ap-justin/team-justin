## v0.12.2 — the standard that didn't fire on seats

**`writing-for-agents` is the authoring standard for both halves of this repo, and its pointer named only one of them.** `SOURCES.md` → *Authoring skills + agents* sends every `agents/*.md` and `skills/*` edit here; `ROSTER.md` → Growing the team makes it step 1 of hiring a seat. The description said *creating or editing skills, or modifying AGENTS.md or CLAUDE.md* — so the 26 seat prompts, the most-edited agent document in the tree, were the one branch it omitted, and a seat edit fired nothing. This is the failure the skill names in its own §Context pointers: a must-have target behind a weakly worded pointer is a variance bug, fixed by sharpening the wording rather than by inlining the material. The `agents/*.md` branch is added and the body stays upstream-verbatim, so the deviation survives a re-sync as a one-line re-apply instead of a merge.

**A provenance note that asserts no drift is worse than none once there is drift.** `SOURCES.md` claimed the skill was *kept verbatim*, which the next re-sync would have read as licence to overwrite the pointer and silently restore the bug; it now names the single deviation and the obligation to re-apply it, and the file's own header comment carries the same instruction where whoever runs the re-download will actually be looking. Both files were diffed against `mattpocock/skills` `main` before the edit and were byte-identical — the standard is current, not stale, so this is the pointer and nothing else.

## v0.12.1 — the brief that banned its own correction

**Step 3 told the lead to hand down "exact paths and ranges," and a lead did** — thirty-odd coordinates across four files, under a *do not re-explore* header. The builder greped anyway, on its first move, and what it turned up was the one thing the map didn't have: the repo's existing row-with-a-control class and the token holding its 44px target floor, in a slice whose whole job was turning a row into a control. That's the shape of the defect rather than an accident of one brief — a coordinate list is complete for what the lead already understood, and it reads as verified whether or not anyone checked it, so the denser it gets the better it conceals the hole where the slice needed something the lead hadn't understood yet. Item 2 of the handoff contract now asks for entry points plus **the half a grep can't return**: the invariant behind why the obvious approach is wrong, the constraint from outside the file, the absence a builder would otherwise have to prove. **Keep the sentence, drop the coordinate.** It's the discipline `references/ui-handoff.md` already gives the token file — point at it, never paraphrase it in — applied to code locations for the same reason.

**The other half was a brief tightening past a seat prompt.** `shared-blocks.md` → Block A already caps what a builder reads *and* names the trigger to stop and ask the lead for paths, so a brief adding *do not re-explore* is that block re-authored stricter — which Step 3's *ambient blocks are handed down by pointer, never re-authored* rule already forbids, except its list didn't name context hygiene. It does now. A new paragraph separates the **hunt** a file list exists to prevent (a builder that doesn't know where to start, sweeping the tree to find out) from the **legwork** it must not (grepping a name, reading the neighbouring rule, checking whether the pattern already exists) — the pass that catches what the map missed. `SKILL.md` 44,894 B → 46,092 B (+2.7%): a patch that adds, on a file the last release cut 27%.

**`issues/` had two writers and no reader.** `lead` Step 4.5 and `/team-justin:issue` both file defects; nothing in the team ever opened the dir again. Step 2.55's intake — the one run that reconciles a stale brief against `git rev-list` and `gh pr list` — read `brief.md`, `IDEAS.md` and `notes/` and never `issues/`, while the skill's own intro promised the grill "reads both artifacts back." The grill now **walks the dir** — each file read against current code, the ones the codebase has since fixed deleted, the survivors surfaced as scope candidates — under the criterion that makes it a pass rather than a glance: *every file accounted for — reproduced, deleted, or explicitly left open*.

**Three gates for one action, and the narrowest ran first.** Step 4.5 opened with "when the project has a plan store **with a `plan/<effort>/`** — no store means only the idea-capture bullet applies"; the defect bullet four lines down said "same no-precondition rule as idea capture"; `TRACKER.md` stated a third, wider version. The gate is now stated **once**, above the bullets — the two captures have no precondition, the two reconciliations need a `plan/<effort>/` — with the duplicates deleted and `TRACKER.md` pointing at it.

**The delete rule was a subordinate clause inside the branch that excludes it.** *Defect capture* leads with "a known bug you're **not** fixing in this slice," so a bug-fix slice answers "no" and never reaches the delete instruction two-thirds through the same bullet. It's now its own bullet — **defect closeout** — with an action (`ls issues/`, read the listing against what you just landed) and the completion criterion its neighbours already had: *every file naming code this slice touched is deleted or explicitly kept*, and "this slice fixed no known bug" is a claim you make **after** the listing, never instead of it. Step 4.5 gains a **report obligation** too — frontier plus `issues/` open/filed/deleted, one line — because the store sits outside the repo, where a skipped sweep is otherwise invisible until it has drifted for weeks.

**`status: open | fixing` had no writer.** Defined in `TRACKER.md`, set by nobody: a defect being fixed right now read identically to an untouched one. The field is gone from the schema and from `/issue`'s template — membership *is* the status, since a fix deletes the file — with the reason recorded so it doesn't grow back: in-flight-ness is session state (the lead's worklist), and a `fixing` value no context reset survives can only ever be stale. `severity` stays, because nothing else carries it. No seat added — the count stays at 26.

## v0.11.0 — the platform is a seat, and the years were wrong

**A third UI builder: `web-components-builder`.** Vanilla custom elements with a shadow root, for UI that has to **outlive a framework** — an embeddable widget dropped into a page the team doesn't control, or a design system consumed by more than one stack. The seam against `react-ui-builder`/`svelte-ui-builder` is the **consumer, not the markup**: a `.tsx` inside a React app stays theirs; a component third-party sites embed is this one's. Its contract is the same props-in/callbacks-out seam in its native spelling — attributes and properties in, `CustomEvent`s out — and what crosses on handoff is a **public API** (tag name, attributes, event `detail`, exposed `part`s and themeable custom properties) rather than a props contract, because once a site embeds it none of those can be renamed. It carries Block D in full: the element's API is a specifiable contract other people's pages depend on, and every one of its failures is invisible on screen.

**`modern-html` — the HTML half of a judgment that only had a CSS half.** `modern-css` has owned "is this platform feature safe to reach for" since v0.7.0 with nothing covering native elements, so a UI builder would compose a headless dialog where `<dialog showModal>` does the job. The new skill carries the newly-native interactive layer (`<dialog>` vs the `popover` attribute, invoker commands, `<details name>`, `inert`, constraint validation, `<output>`, `<search>`, the loading/priority hints) and the **native-first gate that runs before `ark-ui`** — written once, in `ark-ui`'s reach-for section, so the two can't drift. It **defers to `modern-css` for the three Baseline states and the aging rule** instead of restating them. Deliberately **not a semantics primer**: landmarks, heading order and `<button>` over `<div onclick>` are things every model already writes correctly, so including them would fail the skill entry bar — what earns the load is the traps (`<dialog open>` is not modal; a popover is not a dialog; `:invalid` matches a field nobody has touched).

**`web-components` — a skill for failures that don't throw.** The element upgrades, the console is clean, and a keystroke is dropped: a property set before upgrade permanently shadows its own accessor, `connectedCallback` re-fires on every move, an `innerHTML` re-render eats focus mid-typing, and a `CustomEvent` with default options never leaves the shadow root. Not ambient — `web-components-builder`'s playbook, the same posture as `sqlite`. Two `reference/` files carry what only some runs need: `baseline.md` the grouped status table, so `SKILL.md` keeps only the four Limited features it has to design around; `embedding.md` the third-party-embed half: the registration guard, the host's CSP, `position: fixed` breaking under their transformed ancestors, third-party cookies, and the theming contract as a versioned public API. Where the platform doesn't answer it says so — mounting Stripe Elements inside a shadow root is **unverified** (Stripe's docs are silent; `stripe/stripe-js` #143 is closed with no documented resolution), so the instruction is to spike it before the architecture depends on it, not to guess.

**Every Baseline claim was verified against `api.webstatus.dev`, and the drafts written from memory were wrong.** `author.md` requires load-bearing claims to be verified at the source or reproduced; the first drafts of both skills were neither. Checking them moved real numbers: **Popover is Newly available 2025-01-27, not 2024** (the draft contradicted this repo's own `modern-css/reference/baseline.md`), invoker commands landed **2025-12-12** and are eight months old rather than settled, and `:user-invalid` and `<search>` had both **crossed to Widely** in 2026 while the draft still called them 2023 features. Four constraints nobody remembered surfaced only from the data — **scoped custom element registries** and **reference target** are Limited, so a tag name is a global with no escape and ARIA still cannot cross a shadow root, while `adoptedStyleSheets` and form-associated custom elements have been **Widely available since 2023-03**. The CSP claim was corrected from a guess to MDN's actual position: constructed stylesheets are *specified* to need `'unsafe-eval'`, but no browser blocks them — an implemented-behavior fact, not a design guarantee. Both skills now name the read date and the endpoint, so the next reader can recompute rather than trust.

**Roster: 25 → 26 seats.** Blocks B, D, E, F, G, H and I gained the new seat; Block E gains it **by addition, not edit** — the namespacing exception (custom properties inherit across a shadow boundary, so a generic `--primary` on a host page bleeds in) is a bullet after the block, leaving `audit`'s cluster check on the canonical text intact.
