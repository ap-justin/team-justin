# Changelog

Semver-ish: new agent/capability → minor, prompt fix → patch, orchestration-contract break → major.

Last 5 releases only — older entries live in git: `git show vX.Y.Z:CHANGELOG.md`.

## v0.6.0 — a seat per file, not per feature

**The lead routed a React fix list to `stripe-specialist`.** A donation-checkout review came back as eleven findings across eight files — bfcache `pagehide`/`pageshow` semantics, a cross-frame `postMessage` ack, React unmount disposal, a `done` state on a wallet rail, `paypal.tsx` — and the whole list went to the payments seat, which writes no React. Three defects in the routing prompt lined up to produce it, and each is fixed at its own cause rather than papered over with a warning.

**The stripe and auth rows stop paraphrasing a boundary that has its own home.** `stripe-specialist.md` has said *Builder owns: pricing UI, buttons, **redirect/embed wiring**, and the route file* since it shipped; the lead's routing row carried a second, shorter copy — *the pricing page + buttons → the UI builder* — that had quietly dropped the embed clause, which is exactly the clause three of the findings sat under. One boundary in two files drifts, and the lead routes off whichever copy it can see. Both rows now point at the seat's own `Builder owns` line instead of restating it (the discipline Step 3 already asserts for official sources), and each row's triggers are qualified to **the server + money / server + session half** so a `.tsx` under `stripe/` no longer fires them on the directory name.

**The UI seam stops being a roster of three.** It opened *Framework seats (`sveltekit-builder`, `react-router-builder`, `nextjs-builder`) own the network boundary…* — a closed enumeration that left the domain seats outside the rule, so nothing pulled the component half back out of a payments dispatch. It now leads with the property instead of the membership: **only `react-ui-builder` and `svelte-ui-builder` write components**, every other seat hands component implementation across, and **a file's directory does not own it** — `methods/stripe/form.tsx` is a component that happens to live under `stripe/`.

**Splitting gains its missing axis.** The skill has always opened *Delegate on stack, not size*, then defined splitting only by size ("a build that would touch many files/subsystems"). Nothing said to split when the **file set crosses a seam**, so a change list explicitly annotated with paths across four rails read as one unit. Step 3 now carries the grouping rule — **the table picks a seat per file, not per task; more than one group is more than one dispatch** — which doubles as the step's completion criterion (*every file in the change list assigned to a seat*, which a single guess never satisfies). Step 4's fix loop inherits it, since a merged multi-reviewer fix list is where the singular "loop fixes back to the builder" did its damage, and the size bullet now names itself as the other axis.

## v0.5.1 — the pointer is not the payload

**Every conditional skill hook stops carrying the skill's body.** The `zod`, `panda-css`, `superforms`, `drizzle`, motion and 3D blocks each told a seat to load a skill and then handed it a compressed copy of that skill's headline traps — a second home for a meaning that already had one, going stale on its own schedule (the seats' `.prefault()` gloss had already drifted from `skills/zod/SKILL.md`). Each is now a pointer that does a pointer's job: the trigger, one trap as the hook, the operative rule, and the seat's own edge. Those blocks drop from ~2,270 words to ~1,740 across eight seats, with no rule lost — the rules live in the skills, which is where the seats were already being sent. Net agent-body size is roughly flat (−178 words), because the block work below adds back what it closes.

**Three shared blocks get a canonical home.** `## Scope — build the real path` (11 seats), `## Build and return — no self-dispatch` (7) and `## Match the repo` (7) were being copied peer-to-peer with no source and no assertion — the exact mechanism `shared-blocks.md` exists to prevent. They are now **Blocks F, G and H**, each with its invariant clauses, its tailored slots and its exemptions recorded, and `audit` asserts all three. Two real gaps closed on the way: `cloudflare-builder` and `sanity-builder` build renderable output and had never carried Block G, so both could have booted an app or self-dispatched a reviewer. The four `## Before importing anything` headings fold into Block H, one home instead of five.

**Two seats stop being told to do something impossible.** `ux-designer` and `design-director` each carried "ask exactly ONE clarifying question" — a subagent has no user channel, so the step could only end in a stall or in narration. Both now state the read, produce the artifact on it, and return the question under **Open questions**, which is how `planner` had it all along.

**Archeology is out, and the rule is written down.** A seat prompt states what is true now; what a rule replaced, what a seat used to own and which pass was retired change nothing an agent does and go stale unattended. `skills/roster/SKILL.md` carries the rule for every branch, `ROSTER.md`'s hire checklist names it, and the standing instances are gone from the seats and from `ROSTER.md` itself. The *reasons* behind live choices stay — those are what no config confesses; the chronology belongs in this file.

**Staleness swept.** `test-writer` was quoting `tdd`'s retired behavior-list approval instead of its seams step. `postgres-architect` described its integration surface as SvelteKit-only across three framework builders, and said so in its description. `design-director` still declared a Svelte 5 framework target from a seat that writes no code. The model-tier note counted 23 subagent calls against 25 seats. All 25 descriptions — permanently-loaded context pointers — were pruned to their trigger branches, with the three review seats' mutual `Complements X (…) and Y (…)` prose dropped: seat-vs-seat choice is the lead's routing table's job, not three descriptions describing each other.

## v0.5.0 — the states nobody opens

**`/visual-review` stops measuring and starts covering.** The pass was built on *a browser measures better than an eye judges*, and the measuring half turned out to be the wrong half to buy: rect tables, off-scale-vs-token-step audits, contrast ratios and tap-target counts were either duplicating a seat that already owns them or restating what the token file already said. What the user genuinely cannot do themselves is two things, and the pass is now only those. **Coverage** — empty, error, loading, disabled, focus-visible, 375, the row with the 90-character string; in most projects nobody has ever rendered them, so *"this state exists and no one has seen it"* is a finding on its own, reported even when what rendered was fine. **Cause** — a defect the user spots in a second costs them an hour to locate, so the seat returns it as a `file:line` with its scope. Numbers survive only as evidence: one `eval` where the eye is genuinely unsure, inline next to the finding, never a table.

**The lanes stop overlapping.** Contrast ratios and tap-target sizes are `accessibility-reviewer`'s alone — it drives the same browser and carries the criterion number, and a failure measured twice is a failure argued twice. Values outside the token file stay `taste-reviewer`'s grep, a hundred times cheaper than a browser. `visual-reviewer` reports text as *unreadable over what's behind it* and routes the ratio. Six documents that pointed a measurement at this pass now point it at the seat that owns it (`design-critique`, `/taste-review`, `/accessibility-review`, and the three seats' boundaries).

**The outside eye is removed** — `scripts/vision-review.ts`, its npm script, and the doctrine around it in `README.md`, `ROSTER.md`, `SOURCES.md` and `lead`. It shipped last release on the argument that a model which didn't build the page isn't marking its own homework; on its first real test it missed an obvious visible defect. An impression channel that can miss the obvious is worse than no channel, because its `SAW` block reads equally authoritative whether or not it saw anything, and the routing rules around it (confirm the leads, tag the impression, gate on blast radius) were paying upkeep for that. The gate was always the user's glance. The honest correction is to make the sweep better at what a glance can't reach, not to buy a worse glance. `@google/genai` and `sharp` stay — `gen-asset` uses both.

**What did not move:** the judge line. `visual-reviewer` still returns no verdict on intent, conformance is still prevented by a closed token file rather than detected in a browser, and *does the hierarchy read* is still the user's and nobody else's — `/taste-review` now says so explicitly instead of routing it here.

## v0.4.0 — a second pair of eyes

**`visual-reviewer` gains an outside eye.** The captures the sweep already took go through `scripts/vision-review.ts` to a Google Gemini vision model (`gemini-3.1-pro-preview`, the same `GOOGLE_API_KEY` `gen-asset` uses) — a sibling of the `--video`/`--cutout` paths, not a new seat. The value is the **outsideness**: the reader is not the model that built the page, so it isn't marking its own homework, and one API call over a handful of screenshots answers "what does this look like" in seconds — the question the doctrine conceded a browser sweep can't reach and an agent burns twenty minutes failing at.

**It reads; it does not rule.** The prompt is the contract: three sections (`SAW` / `DEFECTS` / `UNSURE`) and no verdict, no score, and **no measurement** — a vision model can't compute a ratio from a raster, and a fabricated number is indistinguishable from a measured one downstream (the rule `accessibility-reviewer` already runs on). `DEFECTS` are **leads**: the seat confirms each one in the capture or with an `eval` before it becomes an ordinary finding carrying the seat's own evidence.

**What comes back routes to the lead and the builders**, gated on **blast radius, not provenance**. A one-line or token-level fix is taken without the user — they are the commit gate, so a cheap reversible diff they can reject costs less than making them the messenger. A change to the token system, a page's composition, or a direction `claude-design` already settled comes back as a **named proposal** they answer. The impression is tagged with the model that wrote it, never laundered into a measurement, and never counted in the severity totals.

**The design gate did not move** — `README.md`, `ROSTER.md` and `/visual-review` still say the verdict on intent is the user's. What changed is that the fix list has one more reader feeding it.

**A `writing-for-agents` pass over v0.3.0's own text**, which the `claude-design` rewrite left with six defects. Two were live. `lead` Step 2 told the lead to dispatch the coverage check *"in parallel with the user's look at the render"* — after the step that scheduled that look had been deleted, leaving an instruction that can't be followed and that `design-director`, `ROSTER.md` and `README.md` had all inherited; it now batches with the gallery's review passes and says plainly there is no second design gate. And `ux-designer`'s opening seam still routed the visual language through `design-director`, contradicting the next three bullets of its own list. The other four were load: the *"the system's own choices aren't reviewable"* rule stated **four times** across `/taste-review` and its seat, now stated once with the leading word **settled** carrying it elsewhere; `design-director` reading a full anti-slop checklist to tick a ledger row, now scoped per mode (and Mode 1 told to read that pack as a fence rather than a view on the look it must not pre-decide); the ~30-name token list cached in five documents that each *also* name the project's token file as the only authority; and two negation-led rules re-pointed at their positive target.

**The token-vocabulary bullet becomes `shared-blocks.md` Block E.** It shipped in v0.3.0 byte-identical across both UI builders and registered nowhere — precisely the cohort drift `/roster audit` step 6 exists to catch and structurally could not. It now carries invariant clauses, a recorded not-on-these-seats list, and two new audit assertions: that both builders match, and that a seat **enumerating** the token names has cached a list living in the repo it's building. The enumeration is gone from both; what stayed is the three shadcn traps no token file confesses (`--accent` is the hover surface, `bg-primary/90`, alpha `--border` in `.dark`). `audit` step 6 also stops trusting its own count of ⚠ clauses and greps for them instead — a countable claim of the kind its step 7 warns about.

**Deps pinned to exact versions** (no carets): `@google/genai` 2.10.0 → **2.16.0**, `tsx` **4.23.0**, and `sharp` 0.34.5 → **0.35.3** — that last one not a pin but a fix: `sharp <0.35.0` carries four high-severity libvips CVEs, and both scripts feed it untrusted input (client photos, screenshots). Every code path both scripts use was re-run against the upgrade.

## v0.3.0 — the director stops drawing

**Design discipline now branches on mode.** Brownfield has no design hop at all: a feature routes `ux-designer` (flow, IA, states, copy) → the builder, which follows the repo's `## Design system` pointer. `design-director` is invoked there only on a builder's **named gap**, an audit/extend request, or a ledger update — inserting art direction into a repo that already has a system is how it ends up with two.

**Greenfield hands the look to `claude-design`.** `design-director` no longer decides palette, type, layout or the signature. It writes a **direction brief** (`design/claude-design-brief.md`) carrying brand and feel, the dials, the element vocabulary `ux-designer`'s inventory implies, and the hard floors — and explicitly lists what it is *not* saying, so the space stays open. The user carries that brief to `claude-design`, iterates on the look there (**the design gate, and the one human-in-the-loop stop in the build** — nothing on the team can fetch it), and brings the result back. The director then **formalizes**: token spec transcribed rather than re-decided, coverage manifest, the gap list split into what needs another `claude-design` pass versus what the director authors, and the floor violations it corrected. Builder Phase 0, the gallery, the coverage check and the per-element retirement into `/_design` all survive unchanged — now fed by the formalized spec. A third mode, **steward**, keeps a shipped ledger (`Status` / `Shipped as` on every manifest row), so what the system actually has is answerable without reading nine directories.

**Token convention: Radix's 12-step model → shadcn's semantic set** (`https://ui.shadcn.com/docs/theming`). The naming convention only — plain custom properties under `:root`/`.dark`, no shadcn or Tailwind dependency, primitives still Ark's. Restrictive on purpose: a closed ~30-name vocabulary makes *"is this value in the system"* greppable, where "is this the right step of a bespoke 12-step ramp" never quite was. Three divergences from shadcn's stock theme, all downstream of the unchanged hard rule *never opacity as a lightener*: solid state steps (`--primary-hover`/`--primary-active`, …) instead of `bg-primary/90`, solid dark `--border`/`--input` instead of `oklch(1 0 0 / 10%)`, and `--success`/`--warning` added. `/taste-review` gained greps for both shadcn-shaped traps plus `--accent` (the hover/selected surface) misused as the brand accent (`--primary`).

**`ui-principles` removed** (`skills/ui-principles/`, 60 entries across seven `reference/` groups). The design system speaks for itself: with the look decided in `claude-design` and formalized into a closed token contract, a value's correctness is settled by whether it has a home in the token file — not by a corpus of craft defaults sitting beside it as a second opinion. `/taste-review` keeps the anti-slop checklist and gains the explicit rule in its place: **the token file is the standard, a deliberate choice you'd have made differently is not a finding, a value with no home in the system is.** Two rules the corpus housed were rehomed rather than lost — the `Detect:` tier discipline now cites `ux-principles`' copy (`design-critique`, `/taste-review`, `SOURCES.md`), and the no-score rule is stated inline where it's enforced (`design-director`, `design-system`). `design-director`'s craft pointer collapses to the hard floors only, and those are now named as what a platform or spec sets — WCAG contrast, the 16px control threshold, target size, visible focus, reduced motion — not what a book prefers.

**The review lane stops re-deliberating the system.** Same principle one step further: with the look decided in `claude-design` and floor-checked once by `design-director` at formalization, a downstream pass that re-derives the system's own numbers re-opens a closed decision and can only produce a finding whose fix is *redesign*. So `/taste-review` **computes no contrast ratios at all** (the bullet is gone), its **banned-palette check is gone** — folded into values-outside-the-token-file, where those hexes are literals someone pasted rather than a verdict on the system's hues — the vendored checklist's **palette, type-default and AI-cluster bans are narrowed in the loader to untokened values only**, and **Locks** now reads as conformance: FAIL a build that adds a second accent or radius, never the system's choice of which. Two cases stay static findings because the system can't have decided them — a pairing the build assembled that was never authored, and text over imagery with no scrim or `prefers-contrast` at all.

**WCAG keeps exactly one carve-out, and it's narrow.** An external standard isn't a preference, so `accessibility-reviewer` still measures — but only **what actually rendered**, where a browser sees what a token file can't (inherited color, opacity stacking, ink over imagery). Its static path no longer recomputes authored token pairs, and a failing pair that turns out to be authored is a **system defect**: one finding, routed to `design-director`, never re-argued per element. `/visual-review`'s contrast bullet narrows to the composed cases on the same rule. `design-director` gains the other half of the contract in Mode 2 — it clears the floors *once*, and nothing downstream is checking behind it.

**Known cost, accepted:** product UI (forms, tables, dialogs, empty states) now has no craft layer at all. `design-taste-frontend` scopes itself to marketing pages by its own line 11, so on those surfaces the pass is the token-file check, `ux-principles` via `ux-auditor` for the journey, and `/accessibility-review` for the floors. `/taste-review` and `SOURCES.md` both say so plainly rather than letting a thin pass read as a clean bill.
